# U-33 – Tilbehørskontroll

Faktisk liste per booking, maks 20 unike navngitte deler med 1–100 stk. Forslag til navn, ikke antall. Utlevering må bekrefte fysisk kontroll og konkret liste eller eksplisitt ingen løse deler. Lagrer i eksisterende customer JSON sammen med status og eksisterende kontrollnotat; ingen migrasjon. Retur låser utlevert antall, krever returnert antall inkl. skadde og skadd antall, beregner mangler. Avvik krever kontrollmerknad. Legacy aktiv booking uten baseline krever manuell dokumentasjonskontroll; ikke konstruert historikk. Samme status/updated_at-sperre som U14; UI krever forventet updated_at. Ingen automatisk gebyr eller depositumstrekk. Ingen eksisterende data endret. Liste gjelder booking, ikke fast mal per fysisk enhet, og ingen tilbehørslager eller QR for deler. JSON er ikke uforanderlig historikk mot privilegerte skript; listene kan inngå i kundens eksisterende API-data, derfor ingen interne fritekstnotater der. Test i isolert database, gjennomgå samtidig håndtering og eventuelle gamle klienter før bruk. Forhåndsdefinert tilbehør per fysisk maskin, kobling til individregister og digital signering gjenstår.
