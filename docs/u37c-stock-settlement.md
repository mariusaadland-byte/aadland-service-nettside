# U-37C – Reservasjon, lageruttak og fakturagrunnlag
U-31 støtter bare prisforespørsel. U-18 mangler dedikert utleieoverføring. Derfor skal ingen ny betalingswebhook, lager-RPC eller Tripletex-postering aktiveres isolert. Implementert ren, ikke tilkoblet beregningsmodell med tester og separat schemautkast som ruller tilbake.

Foreslått livsløp: ved atomisk gruppebooking, lås utleieprodukter og deretter salgsvarer i stabil UUID-rekkefølge. Kontroller kompatibilitet, serverpris, forventet pris, total og fysisk beholdning minus reservert. Opprett gruppe, uforanderlige varelinjer og hold i samme transaksjon, øk reserved_quantity og revision. Ved verifisert full betaling eller eksplisitt godkjent fakturakreditt: bekreft hold, behold reservasjon. Ved faktisk utlevering: trekk fysisk beholdning og reservasjon én gang. Bruk kontrollert utleveringshandling og ikke bare en betalingsmelding. Ved kansellering før utlevering: frigjør reservasjon etter avklart betalingsstatus; ved utløp sjekk at ingen betaling pågår. Betaling etter frigivelse: sperr utlevering og sett avvik/refusjon til behandling, aldri gjenåpne automatisk. Etter utlevering: ingen automatisk retur til lager; kontrollert fysisk retur og separat kreditnota/refusjon. Delt utlevering og delretur er ikke omfattet.
Alle overganger: lås gruppe først, deretter berørte varer sortert; eksakt replay identifiseres fra lagret event og source_reference, konflikt avvises. Den rene modellen er bare én-linje beregning, ikke bevis på idempotens eller tilgang. Database må oppdatere alle linjer, revisjoner, hendelser og gruppestatus atomisk. Lagerhistorikken i U-37B må vise både manuelle og ordrebaserte bevegelser; admin varetelling kan ikke sette fysisk lager under reservert. Ingen reelle lageruttak nå.

Fakturautkast: separate leie- og varelinjer fra frosset ordre, beløp i øre, 25% mva for disse ordinære avgiftspliktige linjene under forutsetning av mva-registrert virksomhet. Depositum utenfor salgsgrunnlag. Linjeavrunding må avstemmes mot Tripletex før integrasjon. Unik referanse per gruppe; ikke automatisk opprett/send faktura eller kvittering. Ved overføring verifiser betalings-/kreditstatus, tidligere posteringer, kunder, kontoplan, mva-kode og avstemming; lagre eksternt ID og idempotensnøkkel; usikkert svar krever oppslag før retry. Tilbakebetaling og kreditnota må være separate, sporbare handlinger. BankID-avtalen må inneholde samme frosne varelinjer.

Neste avhengighet: U-31 atomisk gruppebestilling, inkl. betalings- og kapasitetssperrer. Deretter DB-test av samtidige reservasjoner, avbrutt betaling, replays, utløpsrace, kansellering, utlevering, manuelle lagerjusteringer, rettigheter og regnskapsavstemming. Ingen prod-deploy, SQL-utføring, ekte betaling eller bokføring.
