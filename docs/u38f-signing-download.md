# U-38F – Private dokumentnedlastinger
Implementert serverruter GET /api/customer/signing/[id]/[kind] og /api/admin/signing/[id]/[kind], kind=avtale/bevis. Begge sperret med produksjon + AADLAND_SIGNING_ENABLED + AADLAND_SIGNING_ARCHIVE_ENABLED, ikke satt. Kunde krever verifisert konto og query med eier-ID, admin kun owner. Begge kontrollerer at avtale og gruppe har samme kunde. Ingen offentlige dokumentlenker eller tilgang via kun UUID. Rate limit per autentisert aktør, feil lukket. Original PDF returneres byte-for-byte etter SHA-256-kontroll, også gamle versjoner. Separat bevis-PDF genereres bare etter HMAC og binding (avtale/kunde/hash/vilkår/challenge/tid). Ingen kode eller HMAC-nøkkel i PDF. Nøkkel-ID brukes med server-only JSON keyring av 32-byte base64-nøkler. Bevis-PDF er utskrift av signeringsregistrering, ikke PAdES eller kvalifisert signatur. Ingen betaling eller gjeldende-avtale-godkjenning følger automatisk av historisk bevis. 
Alle svar no-store, attachments, no sniff. Audit må registreres før vellykket respons, logg gjelder autorisert utlevering, ikke faktisk lagret fil. Audit SQL-utkast ruller tilbake, ingen grants eller kjøring. Før aktivering: U-37/U-38 schema, private grants og RLS, nøkkelrotasjon/backup, bytea-format i Supabase, ekte autorisasjons- og DB-tester, Unicode/visuell PDF-test, tilgang fra Min side og admin, retention og begrenset tilgang til audit. Ingen reelle data eller produksjonsendring. Test er lokal logikk, ikke DB/HTTP-integrasjon.
