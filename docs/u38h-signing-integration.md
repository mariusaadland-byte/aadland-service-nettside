# U-38H – Integrasjon av egen signering og utleieflyt
Erstatter boolean signatureVerified i den isolerte U-37G betalingsplanen med kontroll av original-PDF, HMAC-bevis, eier, gruppe, gjeldende avtalepeker, quote digest og vilkår, signeringstid og revisjon. En klientverdi true er ikke tilstrekkelig. Kun betrodd server kan lese bevis og nøkkel; aldri ta disse fra browser. Ved betalingsclaim må alle bindinger revalideres under samme gruppelås som expiry/revision; lagre agreement_id/digest og betalingsreferanse. En endret avtale krever ny signatur og egen vurdering av eksisterende betalingsforsøk. BankID er ikke påkrevd i denne nye modellen.
Utleveringsmodell: bekreftet gruppe, aktuell signatur, full verifisert capture (NOK, ref, null refund), separat depositum hvis aktuelt, signert kontrollrapport og avklart ID-kontroll. Identitetskrav må komme fra serverpolicy. Resultatet er kandidat, ikke statusendring. Fysisk retur aksepteres også ved manglende signatur eller papirarbeid; retur- og økonomisk avvik behandles separat, ingen automatiske trekk. U-36 typed report forblir separat. Legacy admin single-booking writer får sperre dersom group_id finnes i select(*)-rad; gjelder bare grupper, ingen gruppe-RPC implementert. Ved retur må utstyret mottas fysisk og manuelt dokumenteres hvis systemet er sperret.
Før live: actual group reservation/claim/confirm/fulfill/return transactions, server archive read and HMAC verification, same group lock and CAS binding, all legacy writers (customer payment, links, webhooks, cron, deposits and reports) must be isolated from group children. Need verified payment capture policy, deposit handling, physical return UI, U-38 DB and integration tests, real signing routes, expiry vs sign/pay, access controls and outbox. No provider requests, SQL migration, activation or production deployment. Smoke tests only pure decisions and fixtures.
