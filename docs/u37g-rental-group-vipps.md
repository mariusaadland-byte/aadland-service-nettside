# U-37G – Samlet Vipps-betaling (ikke tilkoblet)
Implementert ren betalingsplan og konservativ avstemmingsmodell, ikke aktiv betalingsintegrasjon. Gjenbruk eksisterende Vipps ePayment-klient med unit:rental når den faktiske gruppeintegrasjonen er godkjent. Aldri service-nøkler. Referanse AUG-<gruppe-UUID>, én per gruppe, fast idempotensnøkkel, leie+varebeløp uten depositum. Ingen automatisk capture, cancel, refund eller faktisk provider-kall. Forutsetter verifisert BankID-avtale (serververifisert dokumentbinding), riktig innlogget eier av bestillingen, ikke utløpt hold. For første versjon én betalingsreferanse per ordre; etter terminal avbrutt betaling og frigivelse må kunden starte ny ordre. Ved usikkert svar behold referanse, ikke opprett ny betaling.
Fremtidig claim: atomisk gruppelås sammen med U-37F expiry, sjekk status, eier, beløp, vilkår, signatur og deadline. Sett payment_pending, betalingsreferanse, idempotens, merchant/environment og event payment_start før ekstern create. GET med samme rental-merchant, ikke browser redirect. 404 eller timeout ikke bevis på avbrutt. Fast returadresse er foreløpig eksisterende /betaling/vipps, men den må tilpasses gruppestatus uten å sende den til enkeltbookingens sync. Verifiser provider-format, aggregate/state, PSP-identitet og merchant/environment mot offisiell API og testmiljø før aktivering; strenge krav i modellen kan gi manuell review i stedet for automatikk. Autorisasjon er ikke capture. Capture krever godkjent forretnings-/leveringsflyt; ikke kreve full capture tidligere enn tillatt. Depositum separat. 
Webhook: eksisterende app/api/vipps/webhook/route.js verifiserer signatur og salgssted. Etter autentisering, før legacy RPC, rut AUG-referanser eksklusivt til ny gruppe-reconcile (aldri enkeltbooking, invoice eller service). Ikke slå på ruting før handler er komplett. Webhook kun signal for ny GET. Ikke ta med rå persondata. Full capture i riktig valuta/ref/PSP med ingen refusjon er kandidat for atomisk gruppebekreftelse, ikke bevis på bankoppgjør. Terminal status med eksplisitte nullverdier for åpne reserverte og capturerte midler er kandidat for frigivelse; egen låst release for payment_pending kreves, dagens draft_group_expire gjelder bare aldri-startede holds. Sen betaling, refund, delcapture, ukjent/manglende status -> review; ikke gjenåpne eller trekke lager automatisk. 
Før live: faktisk group RPC for claim/reconcile/release med dedupe og monotont snapshot, avvis stale/out-of-order events, lagre immutable payment event/PSP/merchant/environment, sjekk korrekt Vipps-config og readiness, nye separate RENTAL_GROUP_PAYMENTS_ENABLED og eksisterende public flag, endre legacy writers/lesere, kundeportal og webhook-routing. Mock og testmiljø: feil signatur, feil merchant, wrong ref/PSP/currency, replay, timeout, 404, autorisert men ikke capture, avbrutt, delbetaling, refund, betaling mot expiry, lager og regnskap. Ingen nye API-endepunkter, SQL, ekte betaling eller produksjonsaktivering. Testfil er bare JS-logikk, ikke Vipps testmiljø.
