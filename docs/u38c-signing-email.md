# U-38C – Engangskode og misbruksvern
Node-orchestrator for autorisert kontekst, kodeforespørsel, e-post og signeringsbeslutning. Validerer verifisert auth-e-post, eierskap på gruppe/avtale, gjeldende avtale-ID, pris-/vilkårsbinding, PDF-bytes og aktiv reservasjonsfrist. Ingen kundevalgt mottaker. Før sending skal challenge registreres atomisk; ved manglende leverandørbekreftelse revokeres bare samme ventende challenge. Ingen kode i svar eller DB (bare HMAC); ikke logg providerfeil med rå e-postinnhold.
Første grenser: minimum 60 sekunder mellom sendinger, maks tre kodeutstedelser og fem feilforsøk per konto per rullerende time (på tvers av avtaler/challenges), maks fem feilforsøk per challenge; disse er policyverdier sendt til store, IKKE en aktiv distribuert rate limiter. Legg også IP-baserte grenser og eksplisitt fail-closed RPC allowance. Ved ny kode revoker gammel; ved feil må telleren lagres selv om HTTP-svar er avvisning. Ved vellykket verifisering må kodeforbruk, sletting av MAC og uforanderlig bevis skrives atomisk, med låst gjeldende avtale og gruppestatus. Enhetsfunksjonen returnerer kun beslutning, ikke faktisk signatur.
E-postadapter bruker eksisterende safeResend og rentalEmailConfig, ny AADLAND_SIGNING_ENABLED og VERCEL_ENV=production, ingen offentlig route. Provider-aksept betyr ikke at kunden har mottatt e-posten. Ukjent levering gir ikke signatur. Ingen ekte mail sendt. 
Neste: implementer konkret atomisk store/RPC og test i isolert database (kontoquota, samtidige resend/verify, feilforsøk, expiry, eierskap, avtaleendring). U-38B archive draft og U-37F group draft må verifiseres først. Bruk sameOriginGuard, auth, rate limits og private dokumentendepunkter. Verifiser gjeldende konto og nøkkel-ID igjen ved hver signering. Bruk DB-klokke og atomisk deadline guard. Kundevisning og signeringsbekreftelse med PDF gjenstår. Ingen SQL eller produksjonsendring. Test bruker fiktiv e-post og mock store/send; ingen integrasjonstest mot Resend eller Supabase.
